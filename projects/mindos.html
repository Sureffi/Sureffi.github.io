Overview_

MindOS is a persistent memory system that gives AI conversations continuity across sessions. It stores what the AI learns about you — your identity, knowledge, and conversational history — and retrieves the right context at the right time.

The system uses three distinct memory layers: Identity (always loaded), Knowledge (semantic retrieval), and Episodic (conversation summaries). Each layer serves a different purpose in reconstructing context for natural, continuous interaction.

Retrieval uses a hybrid approach combining BM25 keyword search (30%) with vector similarity search (70%), using Qdrant for storage and Ollama embeddings. This ensures both precise keyword matches and semantic understanding when surfacing relevant memories.

After each conversation, a background task extracts new memories using LLM tool calling — storing episodic summaries, knowledge facts, and identity updates. A consolidation system promotes emerging patterns to confirmed insights over time.

02 //

Features_

Three-Layer Memory

Identity (always-loaded user model), Knowledge (factual semantic retrieval), and Episodic (conversation summaries with metadata).

Hybrid Retrieval

BM25 (30%) + vector search (70%) union merge. BM25 index rebuilt from Qdrant on startup. Embeddings via Ollama nomic-embed-text (768 dims).

Dual LLM Providers

Chat and memory extraction use different providers. Supports Anthropic, DeepSeek, Kimi, and Claude CLI. Provider hot-switchable at runtime.

Background Extraction

After each chat turn, a background task calls the LLM with tool use to extract episodic, knowledge, and identity updates automatically.

Pattern Consolidation

Reviews episodic memories over time, promotes patterns from emerging to confirmed, rewrites the identity narrative, and proposes merges and prunes.

TUI Client

Terminal-based chat interface with the server. Supports export/import of memories across instances for portability.

03 //

Architecture_

System Design

User message flows through FastAPI to the retrieval layer, which loads identity (always) and performs hybrid search for relevant knowledge and episodic memories. The composed context is sent to the chat LLM with optional tool execution. After the response, a background extraction task stores new memories in Qdrant.

The identity layer uses a structured YAML schema (v2) with dot-notation paths for updates. Field aliases handle LLM hallucinations and v1 migration. The entire system is async with Pydantic v2 models throughout.
